Overview

The application handles a single task: migrate one Shape account record into the signed-in user's TinyCloud storage. The Shape service is mocked; OpenKey authentication and TinyCloud KV writes use the real client SDKs.

An administrator creates or replaces a 9-digit migration key through a protected endpoint and shares it with the user outside the app. The user logs into TinyCloud first, supplies an account code or URL and the migration key, then selects Migrate.

Intentional dummy-server boundary The active migration key is held in process memory. It resets to 123456789 on server restart and is not suitable for multi-instance production deployment.

Component Responsibility
SvelteKit UI Enforces login-first ordering, accepts codes or URLs, and runs fetch plus TinyCloud write through one migration action.
Admin endpoint Authenticates the admin bearer token, generates or sets a 9-digit migration key, and returns it to the admin.
Account endpoint Validates the current migration key, resolves the account code, and returns deterministic mock account JSON.
OpenKey Connects the user's wallet and supplies the provider used to sign into TinyCloud.
TinyCloud web SDK Signs in with the narrow manifest and writes the migration envelope to the user's KV space.

Admin and user flows

Admin

  1. Authenticate with the separate admin bearer token.
  2. POST without a body to generate a random 9-digit key, or provide a specific key.
  3. Receive the active key in the JSON response.
  4. Give the key to the intended user out of band.

User

  1. Open the migration app and log into TinyCloud.
  2. Enter an account code, paste an account URL, or arrive through ?code=….
  3. Enter the 9-digit migration key received from the admin.
  4. Select Migrate; the app fetches and writes the account.

Rotation is immediate: once the admin activates a new key, the previous key receives 401 Invalid migration key.

Run locally

Requirements

  • Bun 1.3 or newer
  • A browser capable of completing OpenKey authentication
  • A TinyCloud node at http://127.0.0.1:8000, or a configured remote host

Start the app and dummy API

bun install
bun run dev -- --host 127.0.0.1

Open http://127.0.0.1:5173/?code=shapedemo-account.

Local bootstrap values

Account code shapedemo-account
Account URL https://shape.example/migrate?code=shapedemo-account
Initial migration key 123456789 after each server restart
Development admin token shapedemo_admin_token

Environment

VITE_TINYCLOUD_HOST=http://127.0.0.1:8000
SHAPE_DEMO_ADMIN_TOKEN=replace-with-a-private-admin-token

The development admin-token fallback is disabled in production. A non-development deployment must set SHAPE_DEMO_ADMIN_TOKEN.

Endpoint contracts

POST /api/admin/migration-key

Generates or replaces the active user migration key. Requires Authorization: Bearer <admin-token>.

Generate a random key

curl -X POST \
  -H 'authorization: Bearer shapedemo_admin_token' \
  http://127.0.0.1:5173/api/admin/migration-key

Set a specific key

curl -X POST \
  -H 'authorization: Bearer shapedemo_admin_token' \
  -H 'content-type: application/json' \
  -d '{"migrationKey":"987654321"}' \
  http://127.0.0.1:5173/api/admin/migration-key

Success response

{
  "migrationKey": "987654321",
  "updatedAt": "2026-07-24T20:03:01.308Z",
  "operation": "updated"
}

Expected errors: 400 for invalid JSON or a non-9-digit key, 401 for an invalid admin token, and 503 when production admin auth is unconfigured.

POST /api/account

Fetches one deterministic mock account. Requires Authorization: Bearer <9-digit-migration-key>. 

curl -X POST \
  -H 'authorization: Bearer 987654321' \
  -H 'content-type: application/json' \
  -d '{"accountCode":"shapedemo-account"}' \
  http://127.0.0.1:5173/api/account

accountCode accepts a direct code, a URL with ?code=, a URL with ?accountId=, or a URL whose final path segment is the account identifier.

Expected errors: 400 for a missing or invalid account code and 401 for malformed, expired, or incorrect migration keys.

TinyCloud integration

The app follows the OpenKey and TinyCloud patterns used by TinyCloud's Secret Manager. The TinyCloud SDK is loaded only when the user selects login, keeping the initial UI bundle small.

Manifest scope

{
  "service": "tinycloud.kv",
  "space": "shaperotator",
  "path": "accounts/",
  "actions": ["put"],
  "skipPrefix": true
}

KV location

space: shaperotator
key:   accounts/<accountId>

Stored envelope

{
  "account": { "...mock Shape account fields..." },
  "importedAt": "ISO-8601 timestamp",
  "importer": "xyz.tinycloud.shaperotator"
}

Neither the migration key nor the admin token is included in the TinyCloud record.

Security and trust boundaries

  • Separate credentials: the admin bearer token controls key rotation; the 9-digit migration key only authorizes account retrieval.
  • Server-only state: the active key and admin endpoint logic live under src/lib/server/.
  • No credential persistence: the browser uses the migration key for one request and does not write it to TinyCloud.
  • Narrow TinyCloud capability: the app requests only tinycloud.kv/put under accounts/.
  • No-cache admin response: the key-management endpoint returns Cache-Control: no-store.
Not production authentication A 9-digit shared secret has a small keyspace and the dummy API has no rate limiting, expiry, per-account binding, audit log, or replay protection. Replace this scheme before handling real customer data.

Productionization checklist

  • Replace the in-memory store with durable, atomic storage such as Cloudflare KV, D1, or the Shape service's database.
  • Replace the 9-digit shared secret with high-entropy, expiring, single-use, account-bound migration grants.
  • Add rate limiting, failed-attempt throttling, audit events, and explicit revocation.
  • Replace createMockAccount() with the real Shape API adapter while preserving the ShapeAccount contract.
  • Configure SHAPE_DEMO_ADMIN_TOKEN in the deployment secret store and remove the development fallback from any public staging environment.
  • Add an authenticated administrator UI only if operational users need one; the current requirement is intentionally endpoint-only.
  • Run a real interactive OpenKey login and TinyCloud write against the target environment before release.
